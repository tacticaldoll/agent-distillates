# 信任邊界與驗證瓶頸：系列地圖

## 系列邊界

本系列處理的是 AI 協作中的可信狀態如何成立。它不把問題簡化成「模型會不會犯錯」，而是追問：當輸出可以很流暢、很自洽、很像專業成果時，什麼機制能判斷它是否正確，什麼邊界能授權它是否可信，什麼瓶頸會讓未驗證內容累積成風險。

核心問題鏈如下：

```mermaid
flowchart LR
    A[生成速度與模型行為變動] --> B[大量自洽候選產物]
    B --> C[人類驗證容量有限]
    C --> D[未驗證語意債務累積]
    D --> E[局部正確被誤認為全局可信]
    E --> F[閉環自洽與責任消失]
    F --> G[外部裁決授權信任狀態]
```

本系列的邊界是信任狀態、驗證容量、語意偏差、知識幻覺、code review 權責與外部裁決。它不處理一般 prompt 技巧，不展開術語庫治理，也不把確定性管線、sandbox 權限模型或棕地規格治理全部納入；這些可在其他系列各自展開。

## 概念槽位與角色

本系列最後形成一篇主報告，因為所有材料都服務同一個核心問題：在 AI 協作中，可信狀態不能由生成系統自己宣告，必須被驗證容量、確定性邊界與外部裁決共同約束。各槽位不是平行文章，而是同一條信任鏈的不同失效點。

| 槽位 | 核心功能 | 決策 |
| :--- | :--- | :--- |
| 自洽、正確、可信 | 建立判斷前提：文字流暢與內部一致只是自洽，仍需對應真實系統與授權邊界。 | 保留為主報告起點，並就地自含重述。 |
| 模型漂移 | 說明底層模型行為變動如何讓既有 skill、規格與驗證規則的基準一起移動。 | 保留為第一個緣起案例，支撐「地基在動」的驗證問題。 |
| 技能幻覺 | 說明 AI 產出如何讓組織誤認能力已存在，導致人類觀測者本身失去校準基準。 | 保留為驗證者能力風險，不拆成一般人機協作文章。 |
| 速度陷阱 | 說明生成速度超過審查頻寬後，未驗證產物如何累積成不可見債務。 | 保留為驗證容量模型核心段落。 |
| 靜默語意偏差 | 說明 95% 正確、格式合法、局部可通過的產物如何在邊界條件爆發。 | 保留為語意層失效案例，銜接確定性邊界天花板。 |
| 拓撲補償 | 說明多 agent、多模型 review 能補注意力盲區，但不能補知識盲區，也會增加仲裁負擔。 | 保留為「可用但有限」的結構性緩衝。 |
| 知識回收與對話蒸餾 | 說明可讀結構能回收理解，也能把未驗證推論固化成知識幻覺。 | 合併為知識資產信任段落，避免另開知識管理系列。 |
| AI code review | 說明局部一致性可由 AI 掃描，全局合理性必須由 owner 授權。 | 保留為最具體的責任邊界案例。 |
| 外部裁決 | 將人類、測試、CI、policy、權限邊界與獨立 verifier 定義為信任狀態的授權層。 | 保留為主報告收束模型。 |

## 合併、移出與保留決策

本系列只需要一篇主報告。原因是材料雖然橫跨模型版本、組織能力、生成速度、語法語意、知識蒸餾與 code review，但它們不是多個核心問題，而是同一個核心問題的不同層：自洽候選產物如何在驗證容量不足時被誤升格為可信產物。

本次保留為主報告內部分工段落的子題：

- 模型漂移：作為信任基準會移動的緣起案例。
- 技能幻覺：作為驗證者校準能力可能不存在的案例。
- 速度陷阱：作為驗證容量模型。
- 靜默語意偏差：作為局部正確與全局意圖不一致的案例集。
- 拓撲補償：作為多 agent 檢查的有效邊界。
- 知識回收與對話蒸餾：作為知識資產從候選結構升格為可信資產的條件。
- AI code review 與外部裁決：作為信任邊界的具體工作流模型。

移出本系列的部分不是刪除，而是因為它們回答不同層級的治理問題：

| 去向 | 移出理由 |
| :--- | :--- |
| 語意污染與反向治理 | 污染分類、歷史噪音、上下文最小權限與反向指引屬於輸入材料如何污染注意力的問題；本系列只承接污染穿越後的信任判斷。 |
| 規格與契約治理 | 確定性邊界、規格契約、SSOT 與決定性管線需要落到更具體的產物晉升規則；本系列只建立信任授權原則。 |
| 術語治理 | 穩定鍵、顯示值、錨點與可逆投影是長期語彙制度問題；本系列只討論術語或結構化文字造成的可信錯覺。 |
| 人機協作擴散 | 技能幻覺與團隊能力擴散可延伸為組織能力議題；本系列只保留其對驗證者校準基準的影響。 |

## 生成式展開去向

| 展開類型 | 去向 | 理由 |
| :--- | :--- | :--- |
| 拆分 | 本次不拆分 | 各槽位的不可替代角色清楚，但拆成多篇會讓讀者先看到局部現象，卻延後看到共同信任模型；單篇主報告更能保留「瓶頸 -> 邊界 -> 裁決」的完整因果。 |
| 潛在深化 | 本次展開 | 驗證容量模型、靜默語意偏差三層、拓撲補償天花板、蒸餾可信度與 code review 授權邊界都在主報告中展開為自包含段落。 |
| 跨篇湧現主題 | 本次展開 | 跨篇合讀後浮現的主題是「可信不是輸出屬性，而是經由非同源裁決授權後的狀態」；主報告以此作為總論證。 |

## 後續展開方向

- 可補一篇實務檢核清單，將不同工作流映射到必要裁決者：知識蒸餾、code review、部署、權限變更與安全判斷各自需要不同閘門。
- 可在規格與契約系列中展開「確定性邊界 vs 統計執行層」如何落成 CI、schema、policy engine 與產物晉升規則。
- 可在人機協作擴散系列中展開技能幻覺如何影響團隊訓練、績效指標與能力盤點。
