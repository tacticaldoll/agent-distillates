# 驅動模型與決策權威演化：系列地圖

## 系列邊界

本系列處理的是專案在不同成熟度階段由哪一種模型持有決策權威。核心問題不是「哪種方法最好」，而是：當團隊對行為正確性、品質、流程或完成條件產生分歧時，最後被查閱、被服從、能裁決爭議的是什麼。

這個問題可以整理成一條因果鏈：

```mermaid
flowchart LR
    A[行為分歧] --> B[查閱權威]
    B --> C[辨識當前驅動模型]
    C --> D[看見模型保證]
    D --> E[看見能力邊界]
    E --> F[失敗成本累積]
    F --> G[引入新權威層]
    G --> H[層疊共存]
    H --> I[遷移反模式檢查]
```

本系列的邊界是驅動模型、決策權威、能力邊界、語義缺口、測試正交性、層疊共存、遷移觸發與遷移反模式。它不深入規格驅動開發的完整流程，不提供特定技術棧遷移 playbook，也不把知識文件分層、AGENTS.md 治理或單一事實來源管線納入主題；那些屬於相鄰系列，只在本系列需要說明「權威如何轉移」時就地使用。

## 概念槽位與角色

本系列最後形成一篇主報告，因為材料共同服務同一個分析框架：專案不是抽象地「更成熟」或「更規格化」，而是在爭議發生時把決策權交給不同媒介。五種模型、程式碼驅動的極限、四加一結構、層疊共存與採納反模式都在回答同一個問題：權威落在哪裡，這個權威能保證什麼，又不能保證什麼。

| 槽位 | 核心功能 | 決策 |
| :--- | :--- | :--- |
| 驅動模型定義 | 把模型定義為決策權威分配，而不是工具、文件或流程偏好。 | 保留為主報告起點，使用「分歧時查閱什麼」作為診斷問題。 |
| 五種模型矩陣 | 比較程式碼、測試、技能、準則與規格各自的保證、無法保證與失敗模式。 | 保留為概念地圖，補足能力邊界與語義缺口。 |
| 程式碼驅動極限 | 說明行為偶然化、知識衰減與認知容量閾值如何推動外部權威層出現。 | 保留為演化起點，不獨立成系列內報告。 |
| 測試正交性 | 說明測試回答可驗證性問題，不能被塞進流程成熟度序列。 | 保留為主報告的二維模型，避免把測試誤當必經階段。 |
| 層疊共存 | 說明新模型取得決策權威後，前序模型降格為基礎設施，而不是消失。 | 保留為演化動力學核心。 |
| 遷移反模式 | 說明跳層、儀式化採納與全域強制的共同根因。 | 保留為反例與不適用邊界，並用具體情境錨定。 |
| 實踐範例 | 用診斷走查、同一功能對照與混合狀態範例，把抽象模型落地。 | 本次補寫在主報告中；操作清單與評估範本移入後續 backlog。 |

## 合併、移出與保留決策

本系列只需要一篇主報告。若拆成多篇，讀者會先看到模型枚舉、程式碼驅動極限與演化動力學三個局部觀察，卻延後看見它們其實共同構成一個權威轉移模型。合併後，程式碼驅動的失敗不再只是遺留系統問題，而是「權威邊界被過度延伸」的第一個案例；演化也不再被誤讀成成熟度排序，而是成本、缺口與權威轉移的結果。

本次保留為主報告內部分工段落的子題：

- 驅動模型：作為決策權威的診斷框架。
- 五種模型：作為能力邊界與失敗模式的概念矩陣。
- 程式碼驅動：作為預設模型、零抽象開銷與行為偶然化的起點。
- 測試驅動：作為正交的可驗證性維度。
- 技能、準則、規格：作為流程成熟度軸上的權威層。
- 層疊共存：作為演化不是替換的核心模型。
- 遷移反模式：作為框架的反例邊界與風險控制。
- 實踐範例：作為抽象框架的穩定錨點。

移出本系列的部分不是刪除，而是因為它們回答不同層級的問題：

| 去向 | 移出理由 |
| :--- | :--- |
| 規格與契約系列 | 規格債、差量流程、增量形式化與棕地導入策略屬於規格驅動開發本身；本系列只使用「規格是否真的持有權威」作為採納反模式。 |
| AI 協作治理與知識架構 | 知識住在哪一層、權威文件如何維護、AGENTS.md 如何委派，是知識架構問題；本系列只問這些媒介在特定爭議中是否握有裁決權。 |
| 架構與決定性管線 | SSOT、可逆投影與決定性 pipeline 是讓權威可執行的工程管線；本系列只處理權威選擇與演化，不展開管線實作。 |
| 操作型成熟度評估 | 稽核清單、成熟度評分、特定技術棧遷移 playbook 屬操作層工具，會讓本次概念再結晶過重。 |
