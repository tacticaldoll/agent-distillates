# 人機協作與能力培育：系列地圖

## 系列邊界

本系列處理的是 AI 協作從個人技巧擴散到團隊能力時，為什麼不能只靠工具分發、模板、SOP 或強制採用完成。它不把問題簡化成「會不會寫 prompt」，而是追問：文字介質為何無法完整搬運判斷力，人的觀念化能力如何形成，團隊如何在使用 AI 的同時保護能力培育路徑，以及什麼時候應該拒絕 AI 的介入。

核心問題鏈如下：

```mermaid
flowchart LR
    A[文字介質失真] --> B[外化規則報酬遞減]
    B --> C[判斷力必須內化]
    C --> D[個體能力差異]
    D --> E[團隊品質方差]
    E --> F[擴散策略與適用邊界]
    F --> G[保留手寫與失敗經驗]
    G --> H[可持續的人機協作能力]
```

本系列的邊界是介質失真、外化陷阱、觀念化能力、設問式操作、團隊擴散、何時不用 AI、人才斷層、手寫代碼與裁決權。它不展開一般 AI 信任架構、外部裁決流程、規格治理或術語治理；那些問題只在支撐能力培育與適用邊界時就地使用。

## 概念槽位與角色

本系列最後形成一篇主報告，因為所有材料都服務同一條因果鏈：AI 能放大產出，但無法替代人對邊界、失敗、成本與系統物理性的判斷。若拆成多篇，讀者會先看到「不用 AI」「團隊推廣」「手寫代碼」等局部主張，卻延後看到它們其實都在回應同一個問題：判斷力不能被無損外化，只能被有意識地培育與制度性保護。

| 槽位 | 核心功能 | 決策 |
| :--- | :--- | :--- |
| 介質失真 | 說明文字 artifacts 在人到文字、文字到 Agent 兩段轉換中都會損耗，存在失真預算。 | 保留為主報告起點，建立「更多文字不必然更可靠」的基礎。 |
| 外化陷阱 | 說明模板、checklist 與規則棘輪如何以合規外觀取代實質溝通。 | 保留為管理直覺的反例，連接個人能力與團隊制度。 |
| 觀念化能力 | 說明設問式操作、預測、建模、校準與即時判斷為何抵抗 SOP 化。 | 保留為主報告核心概念，並補成能力模型。 |
| 團隊擴散 | 說明工具培訓無法消除個體起點差異，品質方差會轉移到不可見的判斷品質。 | 保留為組織層問題，形成成熟度階梯。 |
| 不用 AI 的邊界 | 說明完整理解、完全不理解、成本不可預測與強制使用如何改變 AI 的邊際價值。 | 保留為反例與不適用邊界，不拆成獨立報告。 |
| 人才斷層 | 說明 AI 拿走低階工作後，也拿走形成高階判斷的訓練場。 | 保留為長期風險與培育路徑設計。 |
| 手寫能力 | 說明手寫不是速度優勢，而是理解系統物理性與保留裁決權的基礎。 | 保留為結論性支撐，避免把能力培育誤解為反 AI。 |

## 合併、移出與保留決策

本系列只需要一篇主報告。材料雖然橫跨個人操作、團隊管理、專案成本、人才培育與程式碼實作，但它們不是平行主題，而是同一套能力治理的不同層次：判斷力為何不能用文字完整搬運，如何在人身上形成，如何在團隊中擴散，何時應保護不用 AI 的選擇，以及為何手寫核心路徑仍是裁決能力的來源。

本次保留為主報告內部分工段落的子題：

- 介質失真：作為外化策略天花板的原因。
- 外化陷阱：作為規則、模板與管理直覺的失效機制。
- 觀念化能力：作為人機協作真正的瓶頸能力。
- 團隊擴散：作為個體能力差異進入組織後的風險模型。
- 不用 AI：作為能力治理的反例邊界與成本控制。
- 人才培育：作為 AI 時代需要被重新設計的長期路徑。
- 手寫代碼：作為理解、拒絕與裁決 AI 產出的能力基礎。

移出本系列的部分不是刪除，而是因為它們回答不同層級的治理問題：

| 去向 | 移出理由 |
| :--- | :--- |
| 信任邊界與驗證瓶頸 | 自洽、正確、可信與外部裁決是更廣的驗證架構；本系列只取用「人類驗證能力是瓶頸」這個前提。 |
| AI 協作治理與知識架構 | 權威文件、知識分層與治理委託是制度設計問題；本系列只討論它們在能力培育中造成的外化上限。 |
| 規格驅動開發與棕地治理 | 規格、契約與確定性邊界可支撐 AI 使用，但完整 SDD / OpenSpec 採用策略不是本系列主題。 |
| 架構約束與決定性管線 | pipeline gate、SSOT 與 extension point 是系統設計技術；本系列只討論它們作為低風險訓練場或高風險核心路徑的角色。 |

| 展開類型 | 去向 | 理由 |
