# 批次導讀：AI 自洽系統的可信邊界

## 背景

這批結晶報告圍繞同一條弧線展開：先判斷探索成果何時值得回收，再判斷蒸餾內容能信多少，最後處理 agent runtime、code review 與自動化工作流中「自洽不等於可信」的邊界。

## 閱讀順序

1. **知識回收的 ROI：把一次性探索轉成可重用理解**  
   文體：分析論文。摘要：說明蒸餾何時值得做，以及一次性探索如何轉成可重用知識資產。

2. **對話蒸餾的可信度：雙層防禦如何避免知識幻覺**  
   文體：分析論文。摘要：建立主題可信度預估與內容懷疑校驗的雙層防禦。

3. **長時間 Agent 的語境污染：為什麼 Context Window 也是攻擊面**  
   文體：分析論文。摘要：把可信度問題推進到 agent runtime，說明 context state 如何累積污染並影響行動。

4. **AI Code Review 的邊界：局部一致性能被檢查，全局合理性必須被授權**  
   文體：分析論文。摘要：說明 AI review 能檢查局部一致性，但不能替代 owner 對需求、架構與風險的授權。

5. **自動化工作流的外部裁決：為什麼防禦不能只由 LLM 自己生成**  
   文體：分析論文。摘要：收束為工作流設計原則：AI 產生候選結構，非同源機制授權信任狀態。

## 跨報告連結

- [知識回收的 ROI：把一次性探索轉成可重用理解 分析] → [對話蒸餾的可信度：雙層防禦如何避免知識幻覺 分析] (causal: 先判斷是否值得回收，再判斷回收後能信多少。)
- [對話蒸餾的可信度：雙層防禦如何避免知識幻覺 分析] → [長時間 Agent 的語境污染：為什麼 Context Window 也是攻擊面 分析] (refinement: 從報告內容可信度，推進到 agent context 作為語義執行狀態。)
- [長時間 Agent 的語境污染：為什麼 Context Window 也是攻擊面 結論] → [AI Code Review 的邊界：局部一致性能被檢查，全局合理性必須被授權 分析] (facet: context 污染與 code review 自洽都展示了流暢敘事不能替代外部判斷。)
- [AI Code Review 的邊界：局部一致性能被檢查，全局合理性必須被授權 結論] → [自動化工作流的外部裁決：為什麼防禦不能只由 LLM 自己生成 分析] (causal: 一旦承認全局合理性需要授權，就需要設計外部裁決層。)
- [知識回收的 ROI：把一次性探索轉成可重用理解 結論] ←→ [自動化工作流的外部裁決：為什麼防禦不能只由 LLM 自己生成 結論] (facet: 前者處理何時值得保存，後者處理何時可以授權行動，兩者都拒絕把流暢輸出直接等同於價值。)
