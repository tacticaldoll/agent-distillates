# 導讀

**Session**: 2026-03-05-a
**Reports**: 3

## 背景

一個遺留專案在 AI 輔助開發過程中，從無治理狀態逐步建立起完整的文件治理框架、知識萃取管線和術語一致性審計機制。這三份報告分別記錄了框架建立、工具設計和一致性挑戰的經驗與分析。

## 閱讀順序

1. **為遺留專案導入治理框架** `Experience Report` — 從單體指令檔到四層文件階層的設計歷程，涵蓋機制分類、知識庫定位和過渡計畫
   ↓ 框架運作後，如何捕捉產出這些決策的思考過程？
2. **設計知識萃取工具** `Analytical Essay` — 分析對話知識的揮發性問題，以及蒸餾→結晶→沉澱管線的設計邏輯、歸屬路由和一次寫入原則
   ↓ 管線和治理文件運作後，跨文件的一致性如何維護？
3. **當權威文件出錯時** `Experience Report` — 術語審計中發現官方文件與執行時行為矛盾的經歷，建立外部權威驗證優先序

## 跨報告連結

- Report 1 發現階段五（知識庫定位） → Report 2 分析段（歸屬作為路由）（causal: 知識路由表的需求源於 Report 1 將知識庫重定義為債務指標後缺乏正向路由）
- Report 1 發現階段三（機制分類） → Report 3 發現階段一（首次審計）（causal: 機制選擇測試的措辭變更產生了殘留舊術語，成為 Report 3 的審計發現）
- Report 2 分析段（管線拓撲） → Report 3 發現階段五（後設資料殘留）（causal: 管線工具的大幅增強產生了概念重命名，觸發了後設資料陳舊問題）
- Report 1 關鍵教訓 ←→ Report 3 關鍵教訓（refinement: Report 3 將「如何建立規則」深化為「規則被不完美地應用時會發生什麼」——從建立治理到驗證治理）
