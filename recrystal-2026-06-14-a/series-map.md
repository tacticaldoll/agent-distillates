# Agent 認知限制與錯誤表面：系列地圖

## 系列邊界

本系列處理的不是「如何讓 agent 變聰明」，而是 agent 的運算限制如何進入工程系統，形成可觀測、可放大、可被治理的錯誤表面。

核心問題鏈如下：

```mermaid
flowchart LR
    A[無狀態生成] --> B[只看見載入的 token]
    B --> C[因果鏈缺失或錯置]
    C --> D[局部決策錯誤]
    D --> E[共享路徑與文件回寫放大]
    E --> F[系統性錯誤表面]
    F --> G[局部完備性與結構約束]
```

此系列的邊界是 agent 在軟體工程協作中的認知限制、錯誤表面與結構性防線。它不處理模型能力評測、一般 prompt 技巧、產品層 UX，也不把所有治理問題都收進來；信任邊界、外部裁決、語意污染與術語治理可各自形成後續系列。

## 概念槽位與文章角色

本系列的材料不是平行主題，而是一條因果鏈上的多個功能槽位。最後形成一篇主報告，是因為這些槽位共同回答同一個核心問題：agent 的認知限制如何進入工程系統，並被結構設計放大或收窄。

| 槽位 | 核心功能 | 決策 |
| :--- | :--- | :--- |
| 最小推理模型 | 建立「無狀態生成 -> 因果斷裂」的基礎前提，說明為什麼不在可見 token 中的因果不會參與決策。 | 保留為主報告的起點，並就地補入「自洽、正確、可信」的差異。 |
| 程式碼文本落差 | 說明封裝、DRY、runtime 綁定、非同步與語法機制如何讓「看見的文本」不同於「實際行為」。 | 合併為錯誤表面段落，避免分散成多篇風險清單。 |
| 知識外化與回寫 | 說明只保存結論、不保存推理，以及錯誤回寫如何把局部錯誤固化成權威事實。 | 保留為錯誤擴散段落；完整信任邊界與外部裁決流程移入後續系列。 |
| Token 命名空間 | 說明命名碰撞如何在 attention 空間中形成干擾，讓詞彙本身成為錯誤表面。 | 保留為本報告的一個錯誤表面類型；制度化術語治理移入後續系列。 |
| 局部完備性 | 將因果斷裂轉成工程可操作的訊號補回原則。 | 保留為第一層防線。 |
| 結構約束 | 將 extension point 設計轉成「收斂性任務中收窄可犯錯空間」的實作原則。 | 保留為第二層防線，並以 example code 承載。 |
| 驅動模型與決策權威 | 提供「每一層只能保證自己的事」的邊界語言。 | 降級為背景框架，不作為本系列主軸；完整規格與契約治理移入後續系列。 |

## 合併、移出與保留決策

本系列只需要一篇主報告。原因是材料雖然分布在決策權威、程式碼形態、知識外化、命名碰撞與 extension point 設計等不同面向，但它們在因果上並非平行主題，而是同一條鏈的不同段落：agent 的可見 token 限制先造成因果斷裂，工程實作再把斷裂放大為錯誤表面，最後由局部完備性與結構約束收窄錯誤空間。

看似可獨立成篇的子題，本次保留為主報告中的分工段落：

- 決策權威演化：作為「錯誤表面何時需要外部結構」的背景，不獨立成系列主軸。
- 程式碼整潔風險：作為因果斷裂進入程式碼的案例集合，併入錯誤表面段落。
- 命名空間碰撞：作為 token 層級錯誤表面，不移入術語治理系列；後續術語治理系列可再從治理制度角度展開。
- 結構約束與 extension point：作為收斂性任務的主要防線，保留為主報告的實務結論。

移出本系列的部分不是被刪除，而是因為它們回答不同層級的治理問題：

| 去向 | 移出理由 |
| :--- | :--- |
| 信任邊界與驗證瓶頸 | 二次污染、規格回寫與 Requirement 提升需要外部裁決、驗證容量與不可閉環自我授權的模型，超出本系列的認知限制主軸。 |
| 語意污染與反向治理 | 命名碰撞在本系列中只作為 token 層級錯誤表面；污染分類、清理與隔離策略應由污染系列承載。 |
| 規格驅動開發與棕地治理 | 驅動模型與權威邊界在本系列只用來說明「保證不可過度延伸」；規格稀疏期、棕地契約與確定性管線需要獨立展開。 |
| 術語治理 | 本系列只保留 attention 與命名空間碰撞的工程因果；穩定鍵、顯示值、錨點與可逆投影屬術語治理問題。 |

## 生成式展開去向

| 展開類型 | 去向 | 理由 |
| :--- | :--- | :--- |
| 拆分 | 本次不拆分 | 各槽位有明確分工，但都服務同一個核心問題；拆成多篇會迫使讀者在防線尚未建立前先跨篇拼接因果鏈。 |
| 潛在深化 | 本次展開 | 最小推理模型、錯誤表面定義、局部完備性與結構約束都在主報告中補成自包含段落，避免只停留在既有材料的描述深度。 |
| 跨篇湧現主題 | 本次展開 | 跨篇合讀後浮現的主題是「錯誤表面不是單一 bug，而是自由度、不可見因果與權威回寫共同形成的系統空間」；主報告以此作為總論證。 |

## 後續展開方向

- 將 token 命名空間碰撞移入術語治理系列時，可進一步展開穩定鍵、顯示值與命名替代策略。
- 將二次污染與文件回寫移入信任邊界系列時，可接上外部裁決、驗證容量與不可由 LLM 閉環自我授權的問題。
- 將局部完備性落到棕地專案治理時，可補一篇實務清單：哪些訊號應與程式碼同址，哪些知識應留在治理文件，哪些內容不應被集中化。
